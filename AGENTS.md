# Session entry checklist

1. Read ALL of README.md, including the complete original user request, before doing any project work. Read research/preregistration-h21.md and research/next-session.md as well. This is a research program, not a leaderboard-probing exercise.
2. Stay on the Arena session branch. Do not move/delete the checkout or its .git directory. Do not publish datasets, credentials, or large model caches to Git.
3. BEFORE implementation or evaluation, register a falsifiable mechanism, non-fault confounder, layers, fixed parameters, predicted direction/size of DTI change, and multiplicity family in research/. Commit it before observing results. Never edit a locked registration to match a result.
4. Hide WHOLE fault components/segments with a 1.5 km Euclidean buffer. Exclude withheld geometry from labels and every catalogue-derived input, external fault map, sampling rule, feature selection, and hyperparameter selection. Never validate a pretrained full-catalogue submission as if it were out-of-fold.
5. Uncatalogued pixels are UNLABELED. Use positive–unlabeled risk, not a negative target for absent raster labels. Official DTI still has a false-positive penalty against the incomplete reference; report it as unverified mass, not geological proof of absence. Do not replace the official metric with a PU proxy.
6. Exact evaluator: alpha=.2, beta=.8, radius=3 pixels. Remove known catalogue pixels from prediction AND truth BEFORE computing all distances; do not buffer the scoring mask; do not give near-known/wrong-label credit. Log TP_w, FP_w, FN_w and penalty terms.
7. No new submission recommendation unless a reproducible clean current-best comparator exists AND the preregistered, multiple-testing-corrected gate passes. Log rejections and blocked ideas. A new filename is not a new scientific model.
8. Every published factual claim needs an official source with a precise excerpt, a computed evidence path, or an explicit USER-REPORTED / INFERENCE / UNVERIFIED label. No invented scores, timestamps, data access, experiments, or attribution of causality.
9. Do not automate DrivenData website access, sign-in, leaderboard scraping, or submissions; its Terms of Use prohibit automatic monitoring. Scheduled feed may refresh GitHub and permitted official-data endpoints ONLY. Label leaderboard as a dated snapshot. Do not ask for credentials.
10. Run all three passes: implementation/tests; bug and edge-case review/fixes; request-by-request audit. Run .venv/bin/python -m pytest, scripts/check_site.py, and format/hash checks. Update research/next-session.md and evidence/review-passes.json with actual results.
11. Data is regenerable in ignored data/. Download from hash-pinned user-provided transport mirrors; distinguish those from official sources. Review pinned input hashes after any restore. Missing baseline caches are a blocker, NOT permission to invent them.
12. User requested a pull request and merge. Use git for local history/push and gh for PR/checks/merge. Push only the session branch. Verify the merge and Pages build; if permissions block them, state the limitation honestly.
